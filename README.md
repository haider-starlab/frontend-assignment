# FieldOps Console — Frontend Intern Assignment

A take-home assignment for the **Frontend Engineering Intern (ReactJS)** role at Cloudnebula Enterprises.

You'll build an operator console for monitoring and controlling irrigation across
farm sites — a small slice of what our FutureOps platform does.

## Quickstart

```bash
nvm use          # Node 20+
npm install
npm run dev      # http://localhost:5173
```

That's it. There is no backend to run: a complete mock API and event stream are
included and start automatically. You should see a placeholder page and, in the
console, `[mock] FieldOps mock API ready`.

Sanity check — paste this into the browser console:

```js
fetch('/api/summary').then((r) => r.json()).then(console.log);
```

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Vite dev server |
| `npm run build` | Typecheck + production build |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run lint` | ESLint |
| `npm run format` | Prettier write |
| `npm run test` | Vitest, once |
| `npm run test:watch` | Vitest, watch mode |
| `npm run verify` | typecheck + lint + test — **run this before you submit** |

CI runs `npm run verify` on every push. A red badge on your PR is the first
thing your reviewer will see, so keep it green.

## About the dependencies

`package.json` pre-declares the toolchain (React, TypeScript, Vite, Vitest,
Testing Library, MSW, ESLint, Prettier) plus `react-router-dom` for convenience.
Setting that up isn't what we're evaluating, so we've done it for you.

Deliberately **not** installed: a server-state library, a charting library, a
form library, a component library. Which ones you reach for — and whether you
reach for one at all — is signal. Add whatever you want, and give each
non-trivial dependency a one-line justification in `DECISIONS.md`.

Swapping `react-router-dom` for something else is fine. So is switching to
Next.js, though SSR earns no points.

## What you'll submit

A PR in your own repository containing your implementation, plus:

- **`README.md`** — replace this file with yours: how to run it, what's done,
  what isn't, known bugs. Accurate self-assessment scores well here.
- **`DECISIONS.md`** — architecture, dependency justifications, trade-offs, what
  you measured, what you cut. Max 1 page.

See `ASSIGNMENT.md` §7 for the full list.

## Ground rules, short version

- Timebox it. **1–2 days elapsed, ~6–10 hours of work.** A polished 90% beats a
  broken 110%. Cut things deliberately and write down what you cut.
- **AI assistants are allowed.** You'll be asked to explain and modify your own
  code in a follow-up call, so don't ship anything you can't defend.
- Ask questions when the brief is ambiguous, or make a reasonable call and
  document it.
- Please keep your repository **private**. It keeps things fair for other
  candidates.

Good luck — we're looking forward to seeing how you think.
